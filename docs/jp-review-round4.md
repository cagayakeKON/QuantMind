# 日股适配第四轮审查与修复

本轮从 `de38b8e1` 出发，核实用户提供的四项缺陷。它们均是新增 JP 接入路径的问题，未以此修改原市场的业务规则。前端继续使用既有模拟执行、研究和资金图表页面。

| 问题 | 确认与修正 | 边界 |
| --- | --- | --- |
| 手动执行固定旧发布，无法选择新交易日 | 公共输入表单增加显式选择最新发布；保留费用，覆盖旧日期时按新版本重新取对应日窗口 | 选择只读；预案/执行仍校验检查点连续性；历史修订不兼容继续拒绝；运行中固定版本 |
| 新预测误用训练版本研究 | 每笔推理分数携带实际发布、输入日、预测日和 run；共享 quality JSON 与 parquet 保存相同来源；研究按 owned model/day/symbol 逐行读取 | 同日补推保留其他证券原来源；混合版本逐股票分组；无来源旧分数不猜训练/current；原市场请求与缓存规则保留 |
| SHAP 忽略因子映射并可取旧日期 | 公共注册 loader 复用标准 factor reader 的逻辑字段映射，模型字段顺序不变，只读确切输入日；复用实际日常推理的整日筛选与预处理 | 缺少模型字段拒绝；训练阶段分数未保存 split/fold 模型输入，不能用日常推理预处理冒充归因 |
| JP 图表接收旧市场消息/迟到 HTTP | 注册账户读响应附认证身份；JP 校验市场、JPY、用户、租户与模拟模式；请求/响应均绑定账户范围和修订号 | 正确来源的原 chartType/value 消息可接收；未知来源拒绝；纯旧市场延迟接收行为保留 |

逐批自审和子 agent 交叉 review 发现并修正了：管理员别名校验误拒绝、旧刷新函数在切换账户后重新捕获新修订号、partial 补推删除日分片其他证券、无效分数解析、SHAP 与实际推理预处理不同，以及训练产物没有来源的问题。

新 JP 训练在读取前固定实际发布，两个原预测产物保存入口记录 `training:<实际 run>` 来源。发布日历没有未来交易日时，训练来源的预测日为 null，不创造信号执行日；日常推理仍要求有效的后续交易日。训练脚本及 backend 已由原本地训练 orchestrator bind mount，未增加镜像依赖或另造训练协议。旧训练产物不会被批量补写或推测来源。

研究页只对 JP 绕过模型/日期缓存，在新来源加载时先清除旧特征，防止旧价格短暂合并到新分数；缺失来源的分数仍可见，对应价格、因子与归因明确不可用。新训练分数可按实际发布研究价格/因子；训练 split/fold 归因目前明确不可用，实际日常推理的树模型归因覆盖字段映射和预处理。

## 验收边界

此次修复不等于“与美股同模式、所有功能可用”。注册现金执行、检查点、DecisionExchange 与 `metadata.market_default` 仍是架构扩展，需独立审查；任意 Qlib 策略兼容性没有获得证明。实盘、分钟/实时、做空杠杆、远程训练、回放代码/止损、SDK 盘中风险订单、TOPIX volume 及部分公司行动限制仍沿原能力声明保留。

仓库没有 `chart_update` 生产端。本轮验证 HTTP 数据隔离，以及收到正确/错误来源标签的现有消息处理，不宣称新增真实后端资金广播。

Docker 引擎已在上一批安全恢复，未删除或重置数据卷；本轮使用现有真实 Docker/PostgreSQL 运行隔离测试。测试数据、模型、运行报告和私有配置均位于 Git 范围外。四个本地 Compose/启动脚本仍排除提交。
