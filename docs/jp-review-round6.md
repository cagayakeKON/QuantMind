# 日本市场第六轮审查、修复与验证

工作基线为 `8692e1d3`，原市场规则对照 `master@913915e6`。附件 `306f4738-cdf3-4c2f-a4ea-8c84bc0da512/Pasted text.txt` 中四份审查合并为 11 组缺陷，重复描述只计一次，见 `jp-review-round6-matrix.md`。前几轮验证保留其独立历史，测试数字不叠加。

## 本轮修复

- G01：上一轮 JP 扫描保护过宽，导致 JP 去重或失败时 CN 新信号返回成功却未保存。现在按各 JP 任务的 claim 合并共享缓存；失去所有权的任务保留已有结果，CN 仍正常更新。缓存内容与 claim 同时用 Redis Lua CAS 校验，竞争时重新读取并合并。仅 JP 新增的原子操作使用 Sentinel 公开的 master pipeline，纯旧市场仍沿用原保存分支。没有把本轮改成全租户盯盘框架。
- G02：执行价格仍是原始价格，离线 IC/分层收益改从回测记录的不可变发布读取复权研究收盘价。收益区间保持原公共报告的 close-to-next-session-close，未换成训练开盘标签；缺行情不跨日桥接，也未放松策略的因果读取限制。
- G03：JP 回放成交后从注册现金规则获取实际 FIFO 已实现盈亏及消耗成本，统一成交表、日汇总和快照。原账户的移动加权成本算法不变。真实分批买入再部分卖出的验证同时覆盖买卖费用及剩余持仓成本。
- G04：公开回测日期范围使用真正可执行的研究发布，并返回版本；快速、专家回测与优化保留该版本提交。原始行情发布推进、研究发布尚未生成时，不再向用户提供尚不能执行的新日期；提交后发布更新也不漂移本次来源。
- G05：公共交易页对涉及 JP 的市场、用户、租户及模式切换建立请求代次，迟到 status/account/config、异常与 finally 均不能覆盖当前范围，也不能阻止新请求。保留回调同样检查当前范围。非 JP 之间仍保持原页面规则。
- G06：同步检查从缓存历史起点到发布终点的现金交易日核心包，追赶 `days` 窗口之前的缺口。行情、证券主表、TOPIX 缺失时不发布新的有效指针；估值仍是可选输入。该覆盖校验是市场日包证据，不宣称自动补齐每只证券的停牌或未发布公司行动。
- G07：JP 报告的波动率和夏普使用包含首个实际收益的净收益序列，采样与年化定义保持原 RiskAnalyzer 口径。只修 JP 转换层，未改公共原市场指标内核。
- G08：研究 overview 与 run universe 根据认证所有者的 JP 模型/run 或显式市场进入公共 JP 读取，使用该批次逐行预测来源，而非最新模型预测或训练发布。SQL 分页前先过滤 JP 所属模型；缺失或混合来源保留分数并提示限制，批量特征按股票来源解析。
- G09：Engine 股票列表和搜索接入原注册 provider、证券主表及 StockCodeUtil；原始本地日线和估值明确标注来源日期，不借用 A 股索引，也不制造实时或基本面字段。旧市场及未知市场原回退保留。
- G10：Alpha Agent 日本后台使用已有 JapanAdapter 准备固定发布的研究输入，状态读取同一发布的 parquet。只有准备成功且实际 ready 才报告 completed；不调用不支持的通用特征命令，不把离线准备当在线行情同步。
- G11：JP 状态扫描与实际 Qlib writer 使用同一公共路径解析。显式 `QLIB_PROVIDER_URI` 全市场覆盖是原配置规则，本轮保留；无覆盖时真实 JP 缓存的构建、读取和扫描一致。旧市场 scanner 路径不重构。

JP 实盘资金读取也在网络调用前明确拒绝，避免把原券商账户的金额展示为 JPY；这是尚未接入的能力边界，不是实盘适配。相关原 JP 实盘测试必须同步拒绝契约，原非 JP 实盘规则继续验证。

## 范围、规则与限制

用户全量模拟初始化/重置清理历史和停止任务是已有系统规则，本轮未改成市场级重置。不能把初始化 JP 宣传为无损追加账户；选择已存在账户的最新兼容发布只读输入，不等于重置。

无 model/run/market 上下文的旧研究 overview 保留原聚合契约。JP 请求应携带所属模型、run 或显式市场；旧预测缺来源时不能猜测价格与因子。盯盘测试验证单 JP 与 CN 混合及其他任务缓存保留，未据此宣称所有多任务、跨发布并发组合均已实测。

现金回测、检查点、DecisionExchange 和市场默认模型协议仍属于需要独立验收的架构扩展，本轮没有借修 bug 重写所有市场执行协议，也不能宣称与 US 原 Qlib 路径等价。实盘、分钟/实时、做空杠杆、远程 JP 训练、回放代码/止损、SDK 盘中风险订单、缺失 TOPIX volume/价值因子及特殊公司行动等限制保留。明确拒绝入口不代表能力已完成；不填造缺失资料。未运行真实在线同步、完整训练/LLM 或券商交易。

扩大回归发现旧 `flow_super_net` 单位断言失败；从修改前 HEAD 提取原 `_UNIT_SCALES` / `_apply_unit_scales` 已复现，相关业务文件无改动。本次不修这个独立旧问题。四项金额 oracle 的 `10000` / `10000.0` 差异仅改测试为精确 Decimal 数值比较，结构、日期、数量、费用和现金断言保留。首次最终前端全量的两项 JP 实盘旧断言与新增拒绝边界冲突，单独记录并同步测试契约，不回退到读取原券商账户。

三组实现分别自审后由其他子 agent 只读交叉 review，根 agent 复核实际差异。测试使用临时不可变发布、真实 Qlib、PostgreSQL UUID schema 与真实 Redis UUID 键；清理限定测试创建的对象。没有对原账户成交、重置、迁移或补数。
