# 统一多市场接入重构

## 验收目标

所有股票市场共用前端页面和后端业务流程。市场适配器只负责数据、代码、
币种、交易日历/时段、交易单位、价格和交收规则。日股不接实盘。
分钟和实时链路必须实现并用测试数据验证；真实数据源缺失须明确报告，
不得用日线冒充实时行情，也不得把测试验证称为真实行情验收。

保留其他市场行为、现有数据集、模型、账户、交易历史。迁移校验后删除
JP 专用页面、卡片、业务路由、worker 和独立账户运行实现；合理的数据源
和交易规则迁入适配器。修复通用流程中同类市场硬编码。

## 执行顺序与未完成项

1. 市场上下文：公共标识、市场/账户隔离、数据库、Redis、缓存、默认模型、
   WebSocket、任务和策略沙箱；时区、日历、运行状态、幂等锁统一。
2. 账本与模拟：通用账户/订单/撤单/持仓/成交/资金/统计、调度和回放；
   本地落库优先、交收资金、历史规则、并发事务、重启恢复。
3. 策略与研究：股票池、模板、自定义策略、动态仓位、风险、训练、推理、
   通用回测、优化、对比和高级分析；数据版本和信号可知时点。
4. 前端：共用首页、交易控制台、回放、回测中心、行情终端、市场分析、
   模型/策略/股票池管理、数据管理；删除按国家选择整页和业务系统的配置。
5. 数据迁移：备份、幂等迁移、映射、账目核对、暂停旧执行器、切换通用
   执行器、保留只读旧数据备份、移除旧代码及路由。
6. 全矩阵验收：CN/JP 同页面同功能，其他市场回归；真实日线完整链路；
   分钟/实时测试链路及缺源状态；跨市场/用户隔离；迁移账目一致。

以上仍是完整目标，不因部分基础代码通过测试而视为完成。

## 每批 Review 要求

修改 → 针对性测试 → 完整 diff review → 修复 → 复查 → 提交 → 下一批。
正确性、权限隔离、数据安全或回归问题未解决时不得继续下一批。
检查新增国家专用业务分支、上下文遗漏、日期/资金/价格错误、未来数据、
旧调用兼容、重复成交、数据迁移丢失。前端改动必须 typecheck。
只提交代码、测试和文档，不提交数据集、缓存、密钥和本机配置。
